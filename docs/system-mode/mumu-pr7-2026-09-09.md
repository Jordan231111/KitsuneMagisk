# PR7 MuMu qualification and review — 2026-09-09

**PR7 acceptance passed on the exact prepared target below.** System Mode remains experimental and
unavailable in release builds; PR7A and the later parity/device gates are still open.

The review covers roadmap PR1 through PR7. The historical `kitsune` reference is
`c02320a92e9b4b1e1dc25624f9e3d6db2ad3603e`; the reviewed `next-system` starting point is
`ff265de9cf57df1c35d418aeebb5c0e1d3fc609f`. The maintained runtime remains based on official v30.7.
PR7A now targets official v31.0 prerelease before the PR8 parity decision. Neither the historical
fork's `31.0-kitsune` label nor this test record claims that the v31.0 port has already happened.

## Target and preparation

- Chinese MuMuPlayer 1.4.46, existing VM index 0; Android 12/API 32, ARM64, 4096-byte pages.
- Vendor root disabled; SELinux permissive; vendor writable-system mode enabled.
- The selected init directory was prepared as root-owned (the vendor image originally used UID/GID
  65534). This is an exact prepared-target qualification, not support for every stock MuMu image.
- Every lifecycle cold boot used full macOS player shutdown/relaunch. No `adb reboot` or deletion
  of the user-owned VM was used.
- External disk copies were made while the VM was stopped, compared byte-for-byte and checked with
  `qemu-img`. Qualification challenged both persistent system and data restoration, verified three
  fresh boot IDs and init/Magisk-domain execution, and retained a separate clean recovery copy.
- Recovery records, private database copies and the owner-only seal key remain outside the repository.
- External providers and module writers were disabled and the player cold-started before transaction
  snapshots/uninstall. Qualification and exact recovery must not race active third-party writers.
- The uninstalled production guest cannot run root ADB. Its data partition was read without mounting
  or changing it, using `qemu-img` and read-only `debugfs`; the temporary raw audit copy was removed.

## Correctness findings fixed

- Preserve user modules, databases, policy choices, scripts and logs during successful uninstall;
  retain full snapshots for failed-transaction rollback.
- Keep installer/recovery execution alive through daemon shutdown using the existing root service,
  validate its calling UID, drain output after UI loss and isolate mount propagation in the right order.
- Match Doctor's init-directory ownership checks to the installer; recognize the known legacy
  live-policy-only launcher and validated versioned PR7 installs without inventing persistent backups.
- Compare complete SQLite logical contents across qualification boots, retaining raw-byte evidence;
  preserve all rows when normalizing the known legacy v13 database and refuse unknown future schemas
  without deleting them.
- Recreate the runtime on RAM-backed roots, explicitly enable BusyBox standalone mode in init
  shells, set upstream-compatible socket-directory traversal permissions and verify ordinary-UID IPC.
- Finish post-fs-data inline before Android starts zygote; use the upstream `magisk` worker mount
  identity and detach legacy worker views only inside the private installer namespace.
- Reject an unavailable SU connection without trapping; avoid the documented old x86_64 bionic
  `strlcpy` page overread in the affected Zygisk hook.
- Finish module-install cleanup before the next operation reuses its workspace. A real hosted
  Shamiko→LSPosed sequence had exposed deletion of the next operation's `update-binary`.
- Replace stale generated stub classes and prevent case-insensitive filename collisions; separately
  reject Java source keywords after name normalization.
- Pin owned AVD transports and fresh boot identities, use available SDK image names, bound complete
  signer-lane lifecycles and remove reliance on shared unauthenticated API quota for sccache.

## Pinned module profiles

Both profiles use the same Vector v2.2 (3080), CorePatch N-1.0 and HMA-OSS oss-166 releases.
The external profile uses [Jordan231111/ReZygisk v1.0.0-521](https://github.com/Jordan231111/ReZygisk/releases/tag/v1.0.0-521),
commit `8034041f8b0f66dd386fa90fe8d76ec504ffcdd9`. Built-in and external providers are never enabled together.
Legacy SuList and internal DenyList enforcement are off during these interoperability tests.

| Profile | Framework/module status | Functional checks |
|---|---|---|
| Built-in Zygisk | Vector 2.2/API 102 and HMA loaded; only CorePatch N enabled in the isolated Xposed profile. | Passed: own-app downgrade and changed-signer install with the configured CorePatch options; all four HMA queries filtered for the scoped probe, all four visible to the control; 96 SU requests. |
| Built-in off + ReZygisk 521 | External monitor and ARM64 daemon healthy; same Vector/CorePatch/HMA profile. | Same isolated functional checks and 96 SU requests passed. |

CorePatch is tested with locally generated, non-debuggable disposable packages and distinct test
signers. No personal application is modified. HMA is tested with a scoped probe and an
unscoped control querying only a disposable target package through four PackageManager APIs.
CorePatch used its declared `system/0` scope with downgrade, verification and digest options for the
positive checks. Cold reloads made preference changes reproducible; after turning those options off
and cold-reloading, Android again rejected both the downgrade and changed signer. Early attempts
with transitional preferences and unrelated Xposed modules were not used as the accepted matrix.
The release module suppresses callback logs; their absence was not evidence of missing injection.

Temporary probes and test configuration were removed before handoff, and automatic root granting
was returned to Prompt. External Zygisk health is established by its daemon/module behavior; the
upstream manager's built-in-Zygisk indicator is expected to be off for that profile. The existing
auto-tapper was paused for test isolation.

## Boundaries

This proves an experimental System Mode slice on one prepared, permissive MuMu target. Release
System Mode remains disabled. It does not prove physical-phone installation, enforcing vendor init
subcontexts, OTA survival, general Hide/SuList semantics, integrity-attestation bypass or broad
external-provider compatibility. PR7A carries the official v31.0 update; PR8–PR16 retain the parity,
remaining historical-feature, device and release gates. Ordinary Android 6 remains supported while
the selected official upstream still declares minSdk 23; System Mode API 23–24 remains excluded.
